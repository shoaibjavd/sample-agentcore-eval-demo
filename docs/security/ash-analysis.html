Known but not scanner-detected

Two review findings were raised after this report's figures were produced and merged without being addressed. Neither is critical and neither is a vulnerability, but they are open:

  • JWKS fetch blocks the event loop. PyJWKClient is constructed with default lifespan=300 and timeout=30, so the key set is re-fetched synchronously every 5 minutes from inside async middleware, and an unreachable endpoint could stall request handling for up to 30 seconds. Availability, not security. Cheapest mitigation is lifespan=3600, timeout=5; the complete fix offloads the fetch off the event loop.
  • detect-secrets scan always exits 0. It reports to stdout and never fails, so removing continue-on-error would not make secret scanning a gate, even though the other steps would then gate correctly. Proper gating needs a committed .secrets.baseline with detect-secrets-hook.

Section 5 — Remaining coverage gaps

  • grype / syft / opengrep MISSING inside ASH. Container-image and SBOM scanning still did not run. The Python dependency gap is now closed via pip-audit, but OS-level packages in the base image are unscanned.
  • cdk-nag and cfn-nag MISSING inside ASH — as in v1. IaC coverage depends on out-of-band runs, so it is not reproducible from ash alone.
  • Pinning needs a recurring audit — now wired in. This round proved pins go stale dangerously: exact pins are correct for reproducibility but guarantee nothing about vulnerabilities. pip-audit has since been added to the security-scan job, installing each package so transitive dependencies are covered (pip itself was one of the three vulnerable packages and appears in no dependency list). It still only reports — see recommendation 1.
  • Scanner configuration is not versioned. .ash/.ash.yaml was untracked and gitignored, so the exclusions and the recorded reasons for each accepted false positive do not travel with the code. Consequences: CI and any fresh clone report 69 findings rather than 0; the rationale for dismissing them is unrecoverable from the repository; and the next reviewer cannot tell noise from risk without redoing the analysis. The bulk of it (cdk.out/**, notebook run output) is pure artifact exclusion that carries no risk-acceptance implication and could be re-added on that basis alone.
  • Git history is out of scope for a working-tree scan. The historical access key ID and account ID remain reachable via GitHub refs/pull/1,2 and on the Amazon remote's main/dev.
